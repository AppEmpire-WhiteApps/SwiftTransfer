## 1. Общие сведения

### 1.1 Назначение

SwiftTransfer — приложение для переноса личных данных с iPhone/iPad на новое устройство: смартфон или планшет на Android (в первую очередь Samsung Galaxy), а также на другой iPhone/iPad. Приложение помогает перенести контакты, фото, видео, события календаря, напоминания и файлы, проверяет соединение, ведёт пользователя пошаговыми инструкциями и содержит встроенного ИИ-помощника, который отвечает на вопросы о переносе.

Продуктовая логика повторяет референс Smart Switch: **Запуск → Подключение → Выбор данных → Перенос → Готово**, с несколькими способами подключения (Wi-Fi/QR, кабель/внешний накопитель).

### 1.2 Ключевые принципы

1. **Исходные данные никогда не изменяются и не удаляются** — только чтение и копирование (как в FAQ референса: «Smart Switch ничего не удаляет»).
2. **Без облака и аккаунтов** — данные переносятся напрямую по локальной сети или через накопитель. Единственный внешний сетевой запрос — ИИ-помощник (и только текст вопроса + технический контекст без персональных данных).
3. **Без пейволлов, подписок, лимитов, счётчиков, рекламы.** Весь функционал доступен сразу. Никаких «осталось N переносов / N сообщений».
4. **Красивый светлый интерфейс** в бело-голубой гамме с растровыми PNG-иллюстрациями (сгенерированными, не векторными).
5. **Честность о возможностях iOS**: то, что iOS не даёт прочитать (SMS, iMessage, заметки Apple, пароли, приложения), не обещаем — показываем в разделе «Что не переносится» и в ответах ассистента.

### 1.3 Целевые устройства и сценарии

| Отправитель | Получатель | Способ | Требование к получателю |
|---|---|---|---|
| iPhone / iPad | Android / Samsung Galaxy | Wi-Fi + QR, через браузер получателя | Любой браузер (Chrome / Samsung Internet), установка приложения не нужна |
| iPhone / iPad | iPhone / iPad | Wi-Fi + QR / код, приложение на обоих | SwiftTransfer на втором устройстве |
| Android | iPhone / iPad | Wi-Fi + QR, загрузка из браузера Android на iPhone | Любой браузер |
| iPhone / iPad | Внешний накопитель (USB-C/Lightning флешка, SSD, SD-ридер) | «Кабель / накопитель» | Накопитель, видимый в приложении «Файлы» |
| iPhone / iPad | Galaxy по кабелю (силами Smart Switch на Galaxy) | Пошаговая инструкция | Кабель USB-C↔Lightning/USB-C или OTG-адаптер |

### 1.4 Ограничения платформы iOS (учесть в UX и текстах)

- iOS не позволяет стороннему приложению передавать данные «по проводу» напрямую в другой телефон. Поэтому «перенос через кабель» реализуется как: (а) экспорт на внешний накопитель через кабель/адаптер, (б) подробная инструкция по проводному переносу средствами Smart Switch на стороне Galaxy (см. §4.8).
- Недоступны для чтения: SMS/iMessage, история звонков, заметки Apple Notes, голосовые заметки, пароли/связка ключей, Wi-Fi-сети, установленные приложения и их данные, музыка Apple Music (DRM), настройки системы, обои, будильники, данные «Здоровья» (вне скоупа).
- Передача по Wi-Fi работает, пока приложение на переднем плане (кратковременно — в фоне). Экран во время переноса не гасится (см. §4.9).

## 4. Функциональные требования

### 4.1 Первый запуск и онбординг [MUST]

1. Splash / Launch Screen: белый фон, PNG-логотип по центру, без анимаций (системный launch screen).
2. Онбординг — 3 экрана (свайп + кнопка «Далее», «Пропустить» в правом верхнем углу):
   - «Переезд на новый телефон — за несколько минут» (`onb_transfer`).
   - «Контакты, фото, видео, календарь и напоминания» (`onb_data_types`).
   - «Напрямую и безопасно. Данные остаются и на старом телефоне» (`onb_secure`).
3. Последний экран — кнопка «Начать». Онбординг показывается один раз (`@AppStorage("onboardingCompleted")`), повторно — из Настроек.
4. **Разрешения на онбординге не запрашиваются.** Каждое разрешение запрашивается контекстно — в момент выбора соответствующей категории, с экраном-праймером (§4.3.3).

### 4.2 Подключение устройств [MUST]

#### 4.2.1 Выбор роли и целевого устройства

На главном экране две крупные кнопки: **«Отправить данные»** и **«Получить данные»**.

«Отправить» → экран «Куда переносим?»:
- **Android / Samsung Galaxy** (через браузер, без установки приложения).
- **iPhone или iPad** (на втором устройстве нужно приложение SwiftTransfer).
- **Кабель / внешний накопитель**.

«Получить» → экран «Откуда получаем?»:
- **С iPhone / iPad** (режим ожидания с QR).
- **С Android** (iPhone поднимает страницу загрузки, Android открывает её по QR).

#### 4.2.2 iPhone → Android (Web Receiver)

1. iPhone запускает встроенный HTTP-сервер (`NWListener`, TCP, порт выбирается системой).
2. На экране — крупный QR-код со ссылкой `http://<local-ip>:<port>/s/<token>`, ниже — та же ссылка текстом и 6-значный код для ручного ввода (страница `http://<ip>:<port>` спрашивает код).
   - `token` — 128-битный случайный (`SecRandomCopyBytes`), base64url; живёт в рамках одной сессии.
3. Пользователь сканирует QR камерой Galaxy → открывается веб-страница получения (`Resources/WebReceiver`), локализованная по `Accept-Language` / языку приложения.
4. **При первом подключении нового клиента** на iPhone показывается системный по стилю алерт: «Устройство 192.168.x.x хочет получить данные. Разрешить?» — без подтверждения ничего не отдаётся.
5. Подсказка, если нет общего Wi-Fi: «Включите Режим модема на iPhone и подключите Galaxy к нему» (с иллюстрацией и кнопкой открыть настройки).
6. Страница на Android показывает: выбранные категории, количество и размер; кнопки «Скачать всё (ZIP)» и по категориям; под каждой категорией — короткую инструкцию, как импортировать на Samsung (Контакты → Импорт .vcf; Календарь → открыть .ics; фото сохраняются в «Загрузки» → видны в Галерее).
7. Отдача файлов:
   - Контакты — один `contacts.vcf` (vCard 3.0, UTF-8).
   - Календарь — `calendar.ics`, напоминания — `reminders.ics` (VTODO) + `reminders.txt` (читаемый список-чеклист, т.к. не все Android-приложения импортируют VTODO).
   - Фото/видео — потоковый ZIP (режим store, без сжатия, ZIP64 для >4 ГБ) **без промежуточной копии на диске**, + возможность скачать отдельными файлами. Поддержка HTTP `Range` для докачки отдельных файлов.
8. Прогресс на iPhone строится по фактически отданным байтам; на странице Android — по прогрессу браузера.
9. Сервер автоматически останавливается: по кнопке «Завершить», при уходе приложения в фон > 3 мин, при бездействии 10 мин.

#### 4.2.3 Android → iPhone (Web Upload)

1. iPhone в режиме «Получить с Android» показывает QR на страницу загрузки.
2. Страница позволяет выбрать файлы (фото, видео, `.vcf`, `.ics`, любые документы) и отправить их (multipart/form-data, потоковая запись на диск iPhone во временную папку, без загрузки в память целиком).
3. После получения iPhone предлагает: фото/видео → сохранить в «Фото»; `.vcf` → импорт в Контакты; `.ics` → импорт в Календарь/Напоминания; прочее → сохранить в «Файлы» (папка приложения, видимая в Files: `UIFileSharingEnabled`, `LSSupportsOpeningDocumentsInPlace`).
4. Проверка свободного места перед приёмом (`volumeAvailableCapacityForImportantUsage`).

#### 4.2.4 iPhone ↔ iPhone/iPad (P2P)

1. Получатель открывает «Получить → С iPhone/iPad» и показывает QR (содержит имя сервиса, PSK, версию протокола) + 6-значный код.
2. Отправитель сканирует QR (`AVCaptureSession` + `AVCaptureMetadataOutput`) **или** выбирает устройство из списка найденных рядом (Bonjour `NWBrowser`, сервис `_swifttransfer._tcp`) и вводит 6-значный код.
3. Канал: TCP + **TLS 1.3/1.2 с PSK**, выведенным из кода/QR (`sec_protocol_options_add_pre_shared_key`). Незашифрованная передача между приложениями запрещена.
4. Протокол обмена — см. §8.
5. На получателе — подтверждение входящего переноса с перечнем категорий и объёма, кнопки «Принять» / «Отклонить».

#### 4.2.5 Общие требования к подключению

- Анимация поиска: пульсирующие голубые кольца вокруг PNG-иллюстрации телефона.
- Таймаут поиска 60 с → экран «Не удалось подключиться» с причинами, кнопками «Проверить соединение» (§4.11), «Спросить ассистента», «Повторить».
- Отслеживание разрыва (`NWConnection.stateUpdateHandler`, `NWPathMonitor`): авто-переподключение до 3 попыток с экспоненциальной паузой, затем продолжение переноса с места остановки (§4.9).
- Обработка отказа в доступе к локальной сети (`Local Network`) — отдельный экран с объяснением и кнопкой «Открыть Настройки».

### 4.3 Выбор данных [MUST]

#### 4.3.1 Экран «Что переносим»

Сетка/список категорий (PNG 3D-иконки, название, количество, размер, переключатель):

| Категория | Количество | Детальная настройка |
|---|---|---|
| Контакты | N контактов | Выбор групп/аккаунтов (iCloud, Gmail, На iPhone) |
| Календарь | N событий | Выбор календарей, период: «Последний год + будущие» (по умолч.), «Все», произвольный |
| Напоминания | N напоминаний | Выбор списков, «включая выполненные» (выкл. по умолч.) |
| Фото | N фото | Все / альбомы / период / ручной выбор (`PhotosPicker`); «Оригинал HEIC» или «Совместимость (JPEG)» |
| Видео | N видео | Все / альбомы / период; «Оригинал HEVC» или «Совместимость (H.264)» [SHOULD] |
| Файлы | N файлов | Выбор через Document Picker (несколько файлов/папок) |

- Вверху — «Выбрать всё» (как в референсе: по умолчанию выбрано всё доступное).
- Внизу — плашка: итоговый объём, оценка времени (по результату проверки скорости или по умолчанию 15 МБ/с), свободное место на получателе (для iOS-получателя — точное; для Android — предупреждение «убедитесь, что есть N ГБ свободно»).
- Подсчёт количества и объёма — асинхронный, со скелетон-плейсхолдерами; экран интерактивен сразу.
- Блок «Что не переносится» (раскрывающийся) — список из §1.4 и кнопка «Спросить ассистента, как перенести это».

#### 4.3.2 Объём медиатеки

- Размер ресурсов — через `PHAssetResource` (без загрузки данных).
- Фото в iCloud (оптимизированное хранение) — помечаются, при переносе скачиваются с `isNetworkAccessAllowed = true`, статус «Загрузка из iCloud…» на экране прогресса.

#### 4.3.3 Разрешения

Для каждой категории — экран-праймер (PNG-иллюстрация, 2 строки объяснения, кнопка «Разрешить доступ»), затем системный запрос:

| Данные | API iOS 17+ |
|---|---|
| Контакты | `CNContactStore.requestAccess(for: .contacts)`; учесть «Ограниченный доступ» iOS 18 (показать количество доступных + предложение расширить) |
| Календарь | `EKEventStore.requestFullAccessToEvents()` |
| Напоминания | `EKEventStore.requestFullAccessToReminders()` |
| Фото (чтение) | `PHPhotoLibrary.requestAuthorization(for: .readWrite)`; обработать `.limited` |
| Фото (запись на получателе) | `.addOnly` достаточно для импорта |
| Камера | для сканирования QR |
| Локальная сеть | системный запрос при первом использовании Bonjour/листенера |

При отказе — категория в состоянии «Нет доступа» с кнопкой «Открыть Настройки» (`UIApplication.openSettingsURLString`). Категория не скрывается.

### 4.4 Перенос контактов [MUST]

- Чтение: `CNContactStore.enumerateContacts` с ключами `CNContactVCardSerialization.descriptorForRequiredKeys()` + `imageDataKey`.
- Экспорт: `CNContactVCardSerialization.data(with:)` пачками по 500 (без пиков памяти), с фото контакта.
- Заметки контактов не переносятся (требуют спец. entitlement) — указать в «Что не переносится».
- Получатель iOS: импорт через `CNSaveRequest`, политика дублей (выбор пользователя перед импортом):
  - «Пропускать дубликаты» (по умолчанию; совпадение по ФИО + хотя бы одному телефону/email),
  - «Добавлять все».
- Сохраняются идентификаторы созданных записей → «Отменить импорт» в течение сессии (§4.10).

### 4.5 Перенос календаря [MUST]

- Чтение: `EKEventStore.events(matching:)` по выбранным календарям и периоду (запрос предикатами по 1 году — ограничение EventKit на длину интервала).
- Экспорт в ICS (RFC 5545), собственный `ICSWriter`:
  - `VEVENT`: UID, SUMMARY, DTSTART/DTEND с `TZID` (или `VALUE=DATE` для событий «на весь день»), LOCATION, DESCRIPTION, URL, `RRULE` из `EKRecurrenceRule` (FREQ, INTERVAL, COUNT/UNTIL, BYDAY, BYMONTHDAY, BYMONTH, BYSETPOS), `EXDATE` для удалённых повторов, `VALARM` из `EKAlarm`.
  - `VTIMEZONE` для всех используемых зон.
  - Экранирование `,;\` и перенос строк длиннее 75 октетов (folding).
- Подписные/праздничные календари (`.subscription`, `.birthday`) — по умолчанию выключены, помечены «только для чтения».
- Получатель iOS: создание событий в выбранном календаре (или новом «Перенесено с …»), дубли — по UID+DTSTART.

### 4.6 Импорт и перенос напоминаний [MUST]

- Чтение: `EKEventStore.fetchReminders(matching:)` по выбранным спискам.
- Экспорт: `reminders.ics` (`VTODO`: SUMMARY, DESCRIPTION, DUE, PRIORITY, STATUS, COMPLETED, RRULE, VALARM) + `reminders.txt` (по спискам, чекбоксы `[ ]` / `[x]`, дата).
- **Импорт напоминаний на получателе iOS**: из P2P-сессии или из файла `.ics` (полученного с Android/из Файлов) → создание `EKReminder` в выбранном списке или новом списке; подзадачи и вложения — не поддерживаются (сообщить в итоге).
- Отдельная точка входа: Настройки → «Импортировать из файла» (.vcf / .ics) через Document Picker.

### 4.7 Перенос фото и видео [MUST]

- Чтение через `PHAssetResourceManager.requestData(for:options:dataReceivedHandler:)` **потоково** прямо в сокет/ZIP, без загрузки файла в память.
- Имена файлов: оригинальные (`originalFilename`), при коллизии — суффикс. Дата съёмки сохраняется: EXIF внутри файла + mtime в ZIP-заголовке.
- **Live Photos**: фото + парное `.mov` с одинаковым именем; на iOS-получателе — собираются обратно в Live Photo (`PHAssetCreationRequest` с `.photo` + `.pairedVideo`).
- Режим «Совместимость»: HEIC → JPEG (ImageIO, качество 0.9, с сохранением EXIF/GPS), HEVC → H.264 [SHOULD] (`AVAssetExportSession`, только по включённому переключателю, с предупреждением, что это дольше).
- Отредактированные фото: по умолчанию переносится текущая (отредактированная) версия; опция «переносить также оригиналы» [OPTIONAL].
- Получатель iOS: `PHAssetCreationRequest`, сохраняются дата создания, геопозиция, избранное; опционально — создание альбомов с теми же названиями [SHOULD].
- Скрытые фото («Скрытые») не переносятся по умолчанию; опция включения при наличии доступа.

### 4.8 Дополнительные данные через кабель / внешний накопитель [MUST]

Экран «Кабель и накопитель» с тремя вариантами:

1. **Сохранить на внешний накопитель (через кабель/адаптер).**
   - Пользователь подключает флешку/SSD/кардридер к iPhone (USB-C или Lightning-адаптер).
   - Выбор папки назначения через `UIDocumentPickerViewController(forOpeningContentTypes: [.folder])` с security-scoped доступом.
   - Приложение пишет пакет `SwiftTransfer_<дата>/`: `Contacts/contacts.vcf`, `Calendar/calendar.ics`, `Reminders/reminders.ics` + `.txt`, `Photos/ГГГГ-ММ/…`, `Videos/ГГГГ-ММ/…`, `Files/…`, `manifest.json` (список, размеры, SHA-256).
   - Проверка свободного места на томе и формата (предупреждение FAT32: файлы > 4 ГБ не поместятся — предложить exFAT или разбить).
   - После записи — верификация по SHA-256 [SHOULD] и экран «Готово: подключите накопитель к Galaxy и откройте Мои файлы».
2. **Восстановить с накопителя на этот iPhone/iPad** — выбор папки пакета → импорт как в P2P (§4.4–4.7).
3. **Перенос по кабелю напрямую в Galaxy** — подробная пошаговая инструкция (§4.12, гайд `cable_galaxy`): какой кабель нужен (USB-C↔USB-C, Lightning↔USB-C, OTG-адаптер для USB-A), «Доверять этому компьютеру», где найти Smart Switch на Galaxy, что переносится этим способом. Приложение здесь выступает подготовителем: кнопка «Подготовить iPhone» запускает чек-лист (заряд ≥ 50% — `UIDevice.batteryLevel`, свободное место, рекомендация отключить iCloud-оптимизацию фото заранее).

«Дополнительные данные» = файлы и документы из приложения «Файлы» (PDF, DOC/XLS/PPT, Pages/Numbers/Keynote, аудио, архивы), выбранные пользователем. Переносятся всеми способами (P2P, Web, накопитель).

### 4.9 Процесс переноса [MUST]

- Экран прогресса: большой круговой прогресс (градиент голубой), PNG-иллюстрация двух устройств с анимированными «частицами данных» между ними, проценты, переданный/общий объём, скорость (скользящее среднее 5 с), оставшееся время.
- Список категорий с собственным прогрессом и статусами: ожидание / идёт / готово / ошибки (N).
- Кнопки: «Пауза/Продолжить», «Отменить» (с подтверждением).
- `UIApplication.shared.isIdleTimerDisabled = true` на время переноса; плашка «Не блокируйте экран и держите устройства рядом».
- Уход в фон: `beginBackgroundTask` для завершения текущего файла; на iOS 26+ — `BGContinuedProcessingTask` для продолжения переноса с системным индикатором прогресса [SHOULD, через `#available`]. На iOS 17–25 — локальное уведомление «Перенос приостановлен, вернитесь в приложение» (`UNUserNotificationCenter`, разрешение запрашивается контекстно).
- **Возобновление**: при разрыве перенос продолжается с последнего подтверждённого файла и смещения (P2P) / Range-запроса (Web).
- Haptics (`.sensoryFeedback`): успех / ошибка / завершение категории.
- Мелкие ошибки (отдельный файл не прочитан) не останавливают перенос — собираются в отчёт.

### 4.10 Сохранение исходных данных [MUST]

- Отправитель работает **только в режиме чтения**: никаких `CNSaveRequest`, `EKEventStore.remove`, `PHAssetChangeRequest.deleteAssets` на стороне отправителя — проверяется код-ревью и unit-тестом на моках (сервисы-источники не имеют методов записи).
- Экран «Ваши данные в безопасности» (в FAQ и перед стартом): «Перенос — это копирование. На старом устройстве всё останется».
- Целостность: SHA-256 для каждого файла в P2P и пакетах накопителя; при несовпадении — повторная отправка файла (до 2 раз), затем — в отчёт об ошибках.
- Получатель **никогда не перезаписывает и не удаляет** существующие данные; только добавляет.
- «Отменить импорт» (iOS-получатель, в течение 24 ч, из Истории): удаление только созданных в этой сессии контактов/событий/напоминаний/фото по сохранённым идентификаторам (с системным подтверждением удаления фото).
- «Резервная копия перед переносом» [SHOULD]: сохранить пакет (как §4.8) в «Файлы» / на накопитель.

### 4.11 Проверка соединения [MUST]

Отдельный экран (вход с главной, из ошибок, из ассистента). Последовательные проверки с анимированными статусами (ожидание → проверка → ✓ / ⚠ / ✕):

1. **Wi-Fi включён и подключён** — `NWPathMonitor` (`usesInterfaceType(.wifi)`), отдельно — режим модема.
2. **Доступ к локальной сети разрешён** — пробный `NWBrowser`, анализ `.waiting(.dns(PolicyDenied))`.
3. **Режим энергосбережения / Low Data Mode** — `ProcessInfo.isLowPowerModeEnabled`, `path.isConstrained`/`isExpensive` → предупреждение.
4. **Заряд батареи** — < 30% → предупреждение.
5. **Свободное место** на этом устройстве.
6. **Связь со вторым устройством** (если подключено): RTT (10 ping-pong сообщений, медиана), **тест скорости** 5 с / до 50 МБ, потери/разрывы.
7. Для Web-режима: проверка, что страница открылась на втором устройстве (сервер видит запрос).

Итог: карточка «Отлично / Хорошо / Слабое соединение» + оценка времени переноса для выбранного объёма + персональные рекомендации (сблизить устройства, переключиться на 5 ГГц, использовать режим модема, отключить VPN, использовать накопитель). Кнопка «Обсудить с ассистентом» передаёт результаты проверки в контекст чата (§7.5).

### 4.12 Пошаговые инструкции [MUST]

- Контент — в `Resources/Guides/guides.json` (локализуемые ключи) → возможна правка текстов без изменения кода.
- Формат гайда: id, заголовок, обложка (PNG), длительность «≈ 5 мин», шаги (заголовок, текст, PNG-иллюстрация, опционально кнопка-действие → диплинк в приложение).
- Экран гайда: горизонтальный пейджер шагов со степ-индикатором «1 Запуск → 2 Подключение → 3 Выбор → 4 Перенос» (как в референсе), кнопки «Назад/Далее», в конце «Начать перенос».
- Набор гайдов (минимум):
  1. `wifi_galaxy` — iPhone → Galaxy по Wi-Fi (через браузер).
  2. `cable_galaxy` — iPhone → Galaxy по кабелю (Smart Switch на Galaxy, кабели, OTG, «Доверять»).
  3. `storage` — через внешний накопитель (запись и восстановление).
  4. `iphone_iphone` — iPhone → iPhone/iPad.
  5. `android_iphone` — Android → iPhone.
  6. `hotspot` — перенос без роутера через режим модема.
  7. `import_samsung` — как импортировать .vcf/.ics/фото на Samsung.
  8. `not_transferable` — что iOS не позволяет перенести и альтернативы (WhatsApp — встроенный перенос WhatsApp, iCloud-контакты — синхронизация Google, пароли — экспорт из «Пароли» на компьютере и т.д.).
  9. `faq` — частые вопросы (удаляются ли данные со старого телефона — нет; нужно ли держать приложение открытым — да; сколько займёт и т.д.).
- Поиск по гайдам [SHOULD].

### 7.3 Авторизация (TOTP) и хранение ключа

- Ключ формата `llm_totp_{prefix}_{secret}`; **заказчик предоставит позже**.
- Разбор по фиксированным длинам: `prefix = первые 20 символов` (`llm_totp_` + 11), `secret = всё после 21-го символа` (base64url может содержать `_`).
- Токен на **каждый запрос** (не кешировать дольше минуты):
  ```
  minutes = floor(unixTime / 60)
  counter = UInt64(minutes).bigEndian (8 байт)
  code    = base64url_nopad( HMAC-SHA256(key: base64url_decode(secret), data: counter) )
  header  = "Authorization: Bearer " + prefix + "_" + code
  ```
  Реализация — `CryptoKit` (`HMAC<SHA256>`), сервис `TOTPTokenProvider` (actor), с инъекцией часов для тестов.
- **Ключ не хранится в коде открытым текстом** (требование LLMApps):
  - Ключ кладётся в `Config/Secrets.xcconfig` (в `.gitignore`), шаблон `Secrets.example.xcconfig` — в репозитории.
  - Build Phase-скрипт генерирует `SecretsGenerated.swift` (в `.gitignore`), где ключ хранится как XOR-маскированный массив байт со случайной солью, сгенерированной на сборке; расшифровка — только в памяти в момент создания токена.
  - Ключ и токены не логируются, не попадают в краш-репорты, не пишутся в UserDefaults/SwiftData.
- Если ключ не задан (пустая сборка) — вкладка ассистента показывает состояние «Ассистент скоро будет доступен» (PNG `assistant_empty`), остальное приложение работает полностью.
- Рассинхронизация часов: при `401` — один повтор с новым токеном; при повторном `401` — ошибка «Проверьте дату и время на устройстве (Настройки → Основные → Дата и время → Автоматически)».

## 8. Протокол P2P (iPhone ↔ iPhone/iPad)

- Транспорт: `NWConnection` TCP + TLS-PSK; Bonjour-сервис `_swifttransfer._tcp`.
- QR-пейлоад (JSON → base64url): `{"v":1,"svc":"<bonjour-name>","psk":"<32 байта base64url>","code":"123456","name":"iPhone Никиты"}`. При ручном вводе кода PSK выводится из кода через HKDF-SHA256 с солью из TXT-записи Bonjour.
- Фрейминг: `[1 байт тип][4 байта длина заголовка][JSON-заголовок][8 байт длина тела][тело]`; собственный `NWProtocolFramer`.
- Сообщения:
  - `hello` (версия протокола, имя устройства, модель, iOS, свободное место) ↔ `hello`;
  - `manifest` (категории, элементы: id, тип, размер, имя, дата, sha256 — для медиа sha256 может считаться на лету и передаваться в `item_end`);
  - `accept` / `reject` (+ политика дублей);
  - `item_begin` (id, offset), `chunk` (256 КБ), `item_end` (sha256), `ack` (id);
  - `pause`, `resume`, `cancel`, `ping`/`pong`, `error` (код, id элемента);
  - `done` (сводка) → `import_report` от получателя.
- Возобновление: после переподключения отправитель шлёт `resume_request` с id сессии, получатель отвечает списком подтверждённых id и смещением незавершённого файла.
- Несовместимые версии протокола → понятное сообщение «Обновите приложение на втором устройстве».
- Unit-тесты: фрейминг, разбор частичных буферов, возобновление, порча данных (sha mismatch).

## 10. Безопасность и приватность

- Все персональные данные передаются только локально (LAN/накопитель). На сторонние серверы — **только** текст чата ассистента и технический контекст §7.5.
- P2P — TLS-PSK; Web-режим — одноразовый 128-битный токен в URL, подтверждение каждого нового клиента на iPhone, автостоп сервера, только локальные адреса (сервер слушает Wi-Fi/hotspot-интерфейсы, не сотовые).
- Временные файлы (полученные загрузки, конвертированные JPEG) — в `tmp`/`Caches` приложения, удаляются после завершения сессии и при старте приложения.
- Защита файлов: `FileProtectionType.completeUntilFirstUserAuthentication` для временных данных.
- Ключ LLM — §7.3. Никакой аналитики/трекинга в релизе (если заказчик добавит — отдельной задачей).

## 12. Ошибки и пограничные случаи (обязательная обработка)

- Нет Wi-Fi / устройства в разных сетях / гостевая сеть с изоляцией клиентов → подсказка про режим модема.
- Отказ в разрешении (каждый тип) и ограниченный доступ (фото, контакты iOS 18).
- Нет места на получателе / на накопителе (заранее и во время записи).
- Фото в iCloud недоступно для загрузки (нет интернета) → элемент в отчёт ошибок с пояснением.
- Повреждённый/нечитаемый ассет → пропуск с отметкой.
- Блокировка экрана / входящий звонок / уход в фон / низкий заряд (< 10% → предупреждение и пауза).
- Накопитель отключён во время записи → понятная ошибка, частично записанный пакет помечен как неполный.
- Повторный запуск переноса тех же данных → предупреждение о дубликатах на получателе.
- Пустые категории → категория неактивна с подписью «Нет данных».
- Огромные видео (> 4 ГБ) → ZIP64 / предупреждение FAT32.
- Смена языка системы во время работы — корректная перерисовка.

## 13. Тестирование и приёмка

### 13.1 Автотесты [MUST]

- Unit: `TOTPTokenProvider` (сверка с эталонной реализацией из `llmapps_api_docs/examples` на фиксированном времени), `ICSWriter` (повторы, весь день, часовые пояса, экранирование, folding), vCard-экспорт, `ZipStreamWriter` (валидность архива, ZIP64), `WireProtocol` (фрейминг, частичные буферы), `HTTPParser` (Range, multipart), `PromptBuilder` (отсутствие PII в контексте), парсер Markdown, парсер структурированного ответа + фолбэк.
- UI-тесты: онбординг → главная; выбор данных с моками; чат ассистента с мок-клиентом; переключение языков (en/ru).
- Мок-сервисы для всех источников данных и LLM-клиента; `#Preview` для каждого экрана.

### 13.2 Ручная матрица

- iPhone SE (2/3 gen), iPhone 13/14, iPhone 15/16 Pro Max, iPad (любой) — iOS 17.0, 18.x, 26.x.
- Android: Samsung Galaxy (One UI 6+), Chrome и Samsung Internet; ещё одно не-Samsung устройство.
- Сети: роутер 2.4/5 ГГц, режим модема iPhone, сеть с изоляцией клиентов.
- Накопители: USB-C флешка exFAT и FAT32, SSD, Lightning-адаптер.

### 13.3 Критерии приёмки

1. iPhone → Galaxy (браузер): 500 контактов, 3 календаря за год, 2 списка напоминаний, 1 000 фото, 20 видео переносятся; на Galaxy контакты импортируются из .vcf, события из .ics, фото видны в Галерее с корректными датами съёмки.
2. iPhone → iPhone: те же данные появляются в Контактах, Календаре, Напоминаниях, Фото (включая Live Photos); дубликаты при повторе не создаются (политика по умолчанию).
3. Android → iPhone: фото и .vcf из браузера Android сохраняются в Фото/Контакты.
4. Экспорт на накопитель и восстановление с него работают, SHA-256 совпадают.
5. На отправителе после любого переноса количество контактов/событий/напоминаний/фото не изменилось.
6. Разрыв Wi-Fi на 30 с посреди переноса → перенос продолжается без повторной отправки завершённых файлов.
7. Проверка соединения выдаёт результат за ≤ 15 с и корректно детектирует: выключенный Wi-Fi, запрет локальной сети, режим энергосбережения.
8. Ассистент отвечает на языке интерфейса (en/ru проверить), кнопки-действия открывают нужные экраны, при отсутствии интернета показывается корректная ошибка, ключ не встречается в бинарнике открытым текстом (`strings` по `.app`).
9. Все гайды открываются и проходятся до конца, кнопки-действия работают.
10. Интерфейс полностью переведён на все языки релиза, нет обрезанных строк на iPhone SE и при Dynamic Type XXL.
11. Нигде нет пейволлов, лимитов, счётчиков использования и рекламы.
12. 0 warnings, 0 падений в прогонах матрицы, все unit/UI-тесты зелёные.

## 16. Важно для App Store

- **Не использовать** «Samsung», «Smart Switch», «Galaxy» в названии, иконке, подзаголовке приложения и в PNG-иллюстрациях (Guideline 4.1 — копирование, 5.2 — товарные знаки).
